Spray and pray vs targeted outreach

Same 10 interviews. Two very different piles.

1,000 × 1% = 10
applications, spray
=
30 × 33% = 10
messages, targeted

Same 10 interviews. 33× fewer messages to get there.

Last year's slide said 0.1%; the math needs 1% (0.1% of 1,000 is one interview). 1% matches the 1–2 per 100 spray bots get. The point: same outcome, radically less effort — that's the whole case for targeted over spray, which the "Steps" section now builds directly.

The steps of finding a job

The targeted funnel

  1. Find live roles
  2. Score your fit honestly
  3. Tailor from real facts
  4. Find the right people
  5. Write to them
  6. Track and follow up
Remember these six. In ten minutes they become six skills.

Find the people behind the posting

  1. The hiring team: “Meet the hiring team” on LinkedIn
  2. Alumni from your school on that team
  3. Alumni founders. Moda, founded by Waterloo grads, hires Waterloo talent. At Sheridan, start with EDGE.
  4. Ex-colleagues from co-ops, clubs, hackathons

Then go multi-channel: email, LinkedIn, a follow. Without becoming a stalker.

Step 4 of the funnel: find the right people. The next two slides are step 5, writing to them.

Talk about them, not you

Hi! I'm Jordan. I'm a CS student and I'm looking forward to learning from you.

“Great!”

Hi Priya! Your Perception team ships models behind a FastAPI service. I built a FastAPI service at my internship that cut compliance report generation from 40s to 6s.

“Really? Tell me more.”

Perfect your tweet-length intro

“I help [target] achieve [benefit].”

“I help [target] achieve [benefit] without [pain].”

I'm Jordan. I make slow Python services fast.

Backed by exp1: “compliance report generation 40s -> 6s”

Six steps × 30 roles, by hand

That's a full-time job.

So let's hire help.

This is why people spray: targeted works but doesn't scale by hand.

What's an agent?

  1. LLM chat: answers questions
  2. Function calling: the model asks your code to do things
  3. Agent: a goal, a plan, tools, and knowing when it's done

Copilot, not autopilot. You press Submit.

Workflows: predictable, cheaper, faster. Agents: open-ended work. Autopilot job search is brittle, against most sites' terms, and gets accounts banned.

All it takes is a folder

my-agent/
AGENTS.md                 # house rules — what it must and must never do
.agents/skills/
  score-fit/SKILL.md       # one skill, one job
  find-roles/SKILL.md
profile/
  facts.json               # your preferences — confirmed facts, not guesses
  tracker.md                # its memory — status, history, follow-ups

No server, no database. Plain files it reads and edits — that you can read too.

This is the whole trick: point any agent (Antigravity, Claude Code, Cursor, Codex, Gemini CLI) at the folder and it onboards itself from these files.

So we wrote house rules

  1. Confirm facts at setup. Only facts you confirmed go into facts.json.
  2. Cite every claim. Each bullet points to a fact id and the exact string.
  3. Only send what you approved. No auto-submit, ever.

LinkedIn access is opt-in, capped, and stops at any warning. An account I know got restricted after ~190 profile views in a day and 100+ invites over ~5 days.

For real: connect your inbox and calendar

One-time setup, for your own search — today's demo stayed on pasted text.

gws auth login --readonly -s gmail       # check-inbox reads it
gws auth login --readonly -s calendar    # agenda, interview conflicts
  • Read-only scopes. It never sends an email or books an event
  • Set inbox.gmail: true in profile/prefs.yml to turn it on
  • Skip this entirely: every skill also takes pasted emails
gws = the Google Workspace CLI (github.com/googleworkspace/cli). check-inbox already uses it for Gmail; calendar is the same login, same read-only posture.

Automate the watching, not the sending

  1. An invite lands in Gmail → check-inbox matches it to the role and flags it, no one asked
  2. Before the call → find-people pulls a one-page brief on the interviewer
  3. After the call → the transcript lands from your recorder (Otter, Fireflies, Granola...) and debrief runs on it automatically

Automation decides when to run a skill. Never what to send.

Same rule as "copilot, not autopilot" from Part 3: a schedule can trigger check-inbox or debrief, but every draft still waits for approve.

Part 6 of 6

Promote the intern

From your laptop to a product.

You don't have to ship anything

Antigravity itself — the IDE, the Agent manager, or the CLI — already is your personal agent.

  • Keep the skills in .agents/skills/ and just keep asking
  • No deploy, no API key, no hosting bill
  • Good enough for one person's own job search

Everything after this slide is for when you want to hand the agent to someone else, or run it unattended.

Three ways to ship it

PathWhat you bringPick it when
Gemini API Managed Agentsyour AGENTS.md and skills, as they arethe skills already work
Antigravity SDKPython, on your own infrayou want that agent harness inside your app
ADK + agents CLIcode-first agents, graphs, multi-agentyou want full control of tools and flow

Your skills folder is the product

from pathlib import Path
from google import genai

def src(path, target):
    return {"type": "inline", "target": target, "content": Path(path).read_text()}

client = genai.Client()
client.agents.create(
    id="job-search-agent",
    base_agent="antigravity-preview-09-2026",   # check the docs for the current id
    base_environment={"type": "remote", "sources":
        [src("AGENTS.md", ".agents/AGENTS.md")] +
        [src(p, str(p)) for p in Path(".agents/skills").rglob("SKILL.md")]},
)

Or build it with ADK + agents CLI

uvx google-agents-cli setup
agents-cli create job-agent --prototype
agents-cli run "Find ML internships in Toronto for summer 2027"
agents-cli eval run
agents-cli deploy        # Agent Runtime, Cloud Run, or GKE
